# 요구사항과 달성 목표 (R1-R5 / G1-G5)

상태: **R1–R5 요구사항 전부 구현 완료**, **G1–G5 목표 전부 달성**(외부 AWG 크리스털 기준 독립검증 포함), 펌웨어 **bbb_pulse_io v1.7** 기준 (`firmware/main.c`).

> 본 문서의 수치는 모두 실측 검증 결과([VERIFICATION.md](VERIFICATION.md), v1.7 최종본)에서 그대로 인용했으며, 반올림하거나 새로 계산하지 않았다. 명령어 인용은 `firmware/main.c`를 직접 읽고 현재 존재하는 것만 반영했다.

---

## 1. 프로젝트 한 줄 정의

GPIO 핀에 **정밀 타이밍 펄스를 출력**하고, 출력 이벤트에 대해 입력 이벤트를 같은 타임베이스로 상대 측정하는 시스템. 타이밍 분해능은 보드가 제공하는 가장 미세한 결정론적 격자까지 끌어올리고, 그 분해능 주장을 **외부 교정 표준(Keysight 33521B AWG)** 으로 독립 검증한다.

BeagleBone Black(AM335x)은 **PRU-ICSS 200 MHz**를 사용하며, 1개 PRU 명령 = 1 cycle = **5 ns**가 결정론적으로 보장된다. 앞 단계인 BeagleY-AI(AM67A, PRU 없음)의 8 ns(ECAP TSCTR 125 MHz) 기준선을 이어받아 더 미세한 격자로 재현한 것이 이 프로젝트다.

---

## 2. 요구사항 (Requirements, R1–R5)

| # | 요구사항 | 설명 |
|---|---|---|
| **R1** | 임의 펄스 패턴 반복 출력 | 사용자 지정 on/off 시퀀스(ns 단위)를 가능한 한 많이 반복 출력 |
| **R2** | 출력 타이밍 분해능 극대화 | 기본 스케줄러 격자보다 미세한 출력 타이밍 제어 (보드의 HW 최선 격자까지) |
| **R3** | 연속 sub-µs 엣지열 | CPU busy-wait 한계를 넘는 지속적 sub-µs 엣지 생성 (DMA/PRU 등 전용 경로) |
| **R4** | 출력↔입력 상대 윈도우 지연 제어, 드리프트 0 | 한 run 안에서 출력↔입력 지연을 HW 격자 단위로 제어, 같은 카운터 공유로 run 내 드리프트 0 |
| **R5** | 분해능 주장의 외부 독립 검증 | 외부 교정 표준(Keysight 33521B AWG, `TRIG:DEL` 4 ns 격자, crystal-traceable)으로 측정값 M 대 외부 지연 τ 선형 적합 → 기울기 ≈ 1.000 확인 |

## 3. 달성 목표 (Goals, G1–G5)

| # | 목표 | 정량 기준 | BeagleY-AI (AM67A) 결과 | BBB (AM335x) 결과 |
|---|---|---|---|---|
| **G1** | R1 패턴 끊김 없이 반복 | 최대 반복 | ✅ 버스트 256슬롯 | ✅ cmd **0x10** R1 패턴(`off500/on2000/off600/on500/off500 ns`), 버스트 내 지터 0 |
| **G2** | 출력 타이밍 분해능 | 보드 HW 최선 격자 | ✅ **8 ns** (ECAP TSCTR 125 MHz) | ✅ **5 ns** cycle-exact (PRU 200 MHz, `__delay_cycles`) — 스코프 실측(cmd 0x30–0x32). 단, 최소 펄스 폭은 ≈**10 ns**(set+clear 2 사이클, cmd 0x22)이며 cmd 0x20/0x21의 주기는 근사치다 |
| **G3** | 연속 sub-µs 엣지열 | 균일 격자, 지속 출력 | ✅ 32 ns/word (BCDMA) | ✅ cmd **0x21** ≈5 MHz(100 ns/100 ns) / cmd **0x22** ~10 ns 펄스 — PRU 직접 토글, 전용 코어 무중단 |
| **G4** | 출력↔입력 상대 분해능 | HW 격자, run 내 드리프트 0 | ✅ 8 ns | ✅ **런타임 윈도우 포지셔닝 = 정확 5 ns**. cmd **0x43**, PRU **하드웨어 LOOP**(`pru_delay.asm`, zero-overhead 1 cycle/count)로 D 사이클(D×5 ns) 지연 배치 → AWG 외부검증 기울기 **1.0000**, 잔차 **0.16 ns**(13점, τ 0~480 ns). 측정 타임스탬프는 **CT_ECAP.TSCTR**(5 ns 격자, cmd 0x42 기준 잔차 3.2 ns). 드리프트 0(단일 카운터 공유) |
| **G5** | 외부 표준 대비 검증 | 기울기 1.000 ± 0.02, 잔차 ≈ LSB | ✅ 기울기 **1.00015**, 잔차 **1.48 ns**(=8 ns LSB), N=100 평균 | ✅ 기울기 **0.99986**, 절편 **257.6 ns**, 잔차 RMS **3.2 ns**, **251점**(τ 0~1000 ns @ 4 ns 격자), **τ당 N=40 평균**(cmd **0x42**) — Keysight 33521B(크리스털 traceable) 외부검증 **PASS** |

범례: ✅ 달성 · ⬜ 미착수/보류

> ⚠️ G5의 기울기 0.99986은 **PRU 5 ns 틱이 외부 크리스털 기준 대비 정확하다**는 증명이며, 이것과 별개로 "출력이 실제 5 ns 단위로 이산 스텝을 만든다"는 사실(G2)은 스코프로 별도 확인한 것이다. AWG 에코 엣지 자체는 ~8 ns 폭이라 이 축만으로 단일 5 ns 스텝 분해능을 보이지는 않는다.

## 4. 보드별 분해능 한계 (왜 BBB가 5 ns인가)

| 보드 | SoC | 정밀 출력 수단 | 결정론적 격자 |
|---|---|---|---|
| BeagleY-AI | AM67A (J722S) | ECAP TSCTR 125 MHz (PRU 없음, EPWM HRPWM firewall) | **8 ns** |
| BeagleBone Black | AM335x | **PRU-ICSS 200 MHz**(PRU0/PRU1, 파이프라인·캐시 없음) + **CT_ECAP** 자유-카운터(200 MHz) | **5 ns** (명령 1개 = 1 cycle) |

PRU는 파이프라인 스톨·캐시가 없어 명령 = 사이클 = 5 ns가 결정론적으로 보장된다. PRU-ICSS 내 **CT_ECAP.TSCTR** 자유-카운터는 "near" 주변장치라 읽기에 ~2 cycle이 걸리며, IEP 타이머("far", ~14 cycle)보다 빠르기 때문에 타임스탬프 소스로 채택했다(`main.c`의 `CT_ECAP.ECCTL2 = 0x0010` 초기화 참고).

## 5. 정직한 한계

> ⚠️ **입력 엣지 타임스탬프는 소프트웨어 폴링이지 하드웨어 캡처가 아니다.** AM335x BBB 헤더에 PRU eCAP 캡처 입력 핀(**capin**)이 배선되어 있지 않다. 그 결과 입력 엣지 검출은 **R31** 레지스터를 소프트웨어로 폴링하고, 그 순간의 **CT_ECAP.TSCTR** 값(약 2 cycle 읽기 지연)을 타임스탬프로 쓰는 방식으로 대체했다. HW 엣지 래치는 사용할 수 없는 하드웨어 제약이다.

이로 인해 축별 분해능의 성격이 다르다.

| 축 | 방식 | 분해능 근거 |
|---|---|---|
| 출력 생성 (G2) | `__delay_cycles()` 컴파일타임 상수 지연 | 카운터 읽기가 없는 순수 명령열 → **5 ns cycle-exact**, scatter 0 |
| 런타임 윈도우 지연 (G4, cmd 0x43) | **`pru_delay.asm`** HW `loop` 명령, 1 cycle/count, zero-overhead | 지연 자체는 정확 D×5 ns이나, 그 뒤 에코 샘플링은 **R31** 단발 읽기 1회 |
| 타임베이스 타임스탬프 (G5, cmd 0x42) | 트리거 순간과 에코 순간을 각각 **CT_ECAP.TSCTR** 읽기 + tight-poll 루프 | 폴링 루프 granularity가 잔차에 반영됨 (N=40 평균 후 3.2 ns) |

> ⚠️ **PRU IMEM은 8 KB(0x2000)로 제한된다.** 폴링 루프의 언롤 정도(예: cmd 0x42의 4× 언롤)는 이 한도 안에서 정해진 것이며, 무한정 늘려 폴링 오버헤드를 줄일 수는 없다.

> ⚠️ **AWG(33500B 계열)의 트리거 재무장(re-arm)은 ms 단위로 느리다.** 펌웨어 내부에서 n>1 버스트로 여러 샷을 연속 발사하면 대부분 놓친다. 그래서 호스트가 단발(n=1)씩 ~6 ms 간격으로 발사하고 τ당 N회 평균하는 방식으로 우회한다(cmd 0x42 N=40, cmd 0x43 N=40).

개발 초기에는 자기참조 루프백 cmd `0x40`, 자체 staircase cmd `0x41`, eCAP capin 프로브 cmd `0x50`을 내부 cross-check로 사용했으나, 이후 리팩토링으로 펌웨어에서 제거되었다(`firmware/main.c` 현재 스위치문에 없음). 현재 유효한 검증 경로는 외부 AWG 기반 cmd **0x42**(타임베이스 정확도)와 cmd **0x43**(런타임 윈도우 포지셔닝)뿐이다.
