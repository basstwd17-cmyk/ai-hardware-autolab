## 적용한 변경

- `probe_comp_check`: 기본 `evaluation=report`, `n=1`로 한 파형을 취득하고
  호스트에서 값을 계산한다. 이전 계약의 ±1%/정확한 N 판정은
  `evaluation=contract`를 명시한 qualification에서만 실행한다. 안전 검사는 그대로다.
- built-in probe/profile capture: `record_length=100000`부터 시작하며 취득 전에
  장비에 설정하고 실제 readback을 기록한다. 더 큰 정수 또는 `null`(의도된 기존 설정 유지)을
  명시할 수 있다. 이는 5ns 등 모든 측정의 충분한 해상도를 보장하는 값이나 강제 상한이 아니다.
  필요한 시간창/대역/해상도 선택은 에이전트의 몫이다. 취득 후 CSV를 임의로 솎지 않는다.
- Single은 K15 장비의 이전 Nx 횟수를 1로 되돌린다. 기본 관측은 K15 통계 시험을 요구하지 않는다.
- 호스트 통계는 기본 `statistics_level=basic`: 분포 표준편차/지터 계산은 생략하고
  해당 값은 null. `full`을 명시하면 계산한다. 직접 호출하는 계산 함수의 기존 기본 동작은 유지한다.
- 호스트가 작은 `waveform_analysis.json`에 계산 방법, 단위가 표시된 필드,
  실제 파형 통계와 원본 CSV 경로/해시를 저장한다. 보고자는 이 근거를 재사용하고
  명시적 검증 요청/불일치가 있을 때만 재계산한다. 요약 자체가 원본을 대신하지는 않는다.
- `read_run`: 기본은 구조화된 요약. 긴 명령/회차 배열은 앞뒤 예시와 생략 위치·개수를
  표시하며 scalar 결과, 오류, 경고, 아티팩트 해시를 유지한다. `detail=full`로 원문 조회 가능.
  JSON을 200KB에서 문자열로 자른 뒤 파싱해 가짜 오류를 만들던 경로도 제거했다.
- 모든 autonomous 에이전트 입력에서 중복 workspace 감사 목록을 참조로 바꾼다.
  시나리오, 피드백, Plan, 권한, 실제 측정값, 실패와 검사 결과는 유지한다.
- 지침은 요청 기반 완료 판정, 필요한 파일 우선, 관련 검사만 수행하도록 정리했다.
  에이전트 추가, 새 승인, 새 필수 Plan 필드, 임의의 테스트/재시도 상한은 추가하지 않았다.

장비 명령 근거: R&S RTM3000 User Manual 1335.9090.02, v11 p.455–456,
`ACQuire:POINts[:VALue]` (`tmp/pdfs/RTM3000_UserManual_en_11.txt`).
100 kSample은 매뉴얼의 지정값이며 장비는 가까운 지원값을 선택할 수 있어 readback을 별도로 기록한다.

## 적용/검증 경계

변경은 플랫폼 소스와 지침에 적용했다. 운영 서비스는 재시작하지 않았다.
프런트엔드 변경이 없으므로 웹 빌드는 필요 없다. 데몬 재시작 뒤 **새 job**에서
확인한다. 기존 격리 workspace의 레시피·서명·run을 소급 변경하지 않는다.
모델/실물 장비 재실행 없이 관련 오프라인 회귀를 검증한다.
다음 실제 job에서는 취득 횟수·CSV 크기·완료까지의 턴 수·캐시/비캐시 입력을 비교해야 한다.

검증: 최종 측정/드라이버/명령 경계/관련 루프 회귀 **96 passed** (12.92초).
MCP·런타임·작업공간/문맥 관련 묶음은 **140 passed, 2 skipped** (24.47초,
앞 묶음과 일부 중복). 새 테스트는 1회 관측, 명시적 qualification 유지, 큰/기존
레코드 설정 허용, 프로브 불일치 차단, 명령 경계, 실제 기본 profile 경로,
큰 JSON의 요약/원문 복구, 시나리오·승인·실패 보존을 확인한다.
문법 검사와 선택된 변경의 `git diff --check`도 통과했다. 프런트엔드는 변경하지 않았다.
