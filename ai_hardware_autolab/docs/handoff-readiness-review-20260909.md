대상: job_c286c36bd46d, job_c275ab1fbb37, job_812c4c3098ce.
운영 원장은 읽기 전용으로 확인했다. 세 job은 사용자 취소 상태이며 재개하지 않았다.
이 문서는 장비 검증 성공 보고서가 아니다.

## 원인과 변경

1. **새 제안/기존 계약의 서로 다른 경로**: 기존 generated boundary도 동일 정규화를
   거친다. 달라진 경우 원본 이름/해시를 normalized_from에 남긴 새 내용 기반 계약을
   만들고 해당 Plan의 참조만 바꾼다. 과거 계약·승인·원문 run은 수정하지 않는다.
2. **계획은 통과했지만 실행 입력이 불완전**: native 도구는 실제 Campaign 제안기가
   쓰는 검사로 Plan 단계에서 준비 가능성을 확인한다. 실패는 기존 Lead 교정 경로로
   전달되며 실행 가능한 Plan이나 빈 승인 요청을 먼저 기록하지 않는다.
3. **SRAM 파일/승인 연결 누락**: 실제 후보·설계 해시·소스·XCF·장비 정보를 오프라인
   검사하고 bitstream/XCF/source/contract/board-map 해시를 step.artifacts에 넣는다.
   경로/해시 두 필드만 있는 임시 후보를 완성된 드라이버 계약으로 오인하지 않는다.
   실제 program_xcf 인자도 준비한 이름과 일치해야 한다.
4. **첫 접촉 후 입력 오류 발견**: 같은 SRAM 입력 검사를 실제 MCP handler의 JTAG
   스캔 앞에서도 호출한다. 이는 승인 부여가 아니며 현재 실행 게이트를 대체하지 않는다.
5. **불완전한 결과의 재검색**: list_contracts는 준비 미완료 생성 계약을 기본 제외한다.
   include_unready=true로 검토할 수 있고 read_contract는 원문과 준비 문제를 제공한다.
   not_flagged는 구조 점검에서 지적이 없다는 뜻일 뿐 장비 성공/승인/파일 무결성 증명이 아니다.
6. **실패한 초안 파일 누적**: 새/정규화 계약을 메모리에서 준비하고 모든 단계의 검증이
   통과한 뒤 참조된 문서만 create-only로 저장한다. 뒤 단계의 검증이 실패해도 앞 단계의
   초안이 디스크에 남지 않는 회귀 테스트를 추가했다. 승인 기록을 소급 변경하지 않는다.
