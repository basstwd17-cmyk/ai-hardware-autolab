# 웹에서 에이전트 모델 선택

Start 또는 Settings → **모델 목록 불러오기** → 공통 모델 선택.
필요하면 **에이전트별로 다르게 선택**을 펼쳐 Lead·Builder·Verifier를 각각 지정한다.
추론 강도는 선택한 모델의 실제 지원 목록에서 고른다. 다른 모델로 바꾸면 이전 강도는 초기화한다.

- 현재는 **로컬 Codex CLI 모델만** 지원한다. Claude / Ollama / 다른 API 공급자를 연결한 기능은 아니다.
- 모델 목록은 데몬 PC의 CLI `model/list`에서 가져온다. 로그인은 CLI가 소유하며 인증 파일을 읽거나 토큰을 웹에 보내지 않는다.
- 목록 조회는 thread/turn을 만들지 않는다. 메타데이터는 5분 캐시하며 요청 실패 시 임의 모델 목록으로 대체하지 않는다.
- 아무것도 선택하지 않으면 기존 `--lead-agent-model`, `--builder-model`, `--verifier-model` 및 Codex 기본 설정이 그대로 적용된다.
- 공통 모델 선택은 3개 역할에 적용되고, 역할별 선택이 있으면 해당 역할만 덮어쓴다.
  역할별 모델을 고르면 추론 강도도 그 모델의 기본값 또는 사용자가 고른 값이며, 다른 공통 모델의 강도를 이어받지 않는다.
- 브라우저 선호 설정은 `localStorage`에 저장한다. 다른 PC/휴대폰 브라우저와 자동 동기화하지 않는다.
- 작업 시작 시 검증된 선택값을 `Brief.inputs.model_selection`에 복사한다. 재개/반복은 이 값을 사용한다.
  이후 Settings 수정은 이미 실행 중인 job을 바꾸지 않는다. 같은 시나리오라도 모델 설정이 다르면 별도 작업으로 시작한다.
- 모델과 추론 강도는 `thread/start.model`, `turn/start.model/effort`에 적용된다. 장비 권한·작업공간·승인 조건은 바뀌지 않는다.
- `execution: direct`는 Builder 모델 턴 없이 도구를 직접 실행하므로 Builder 모델 선택과 무관하다.
- 모델 목록에 있다는 것은 호출 성공·무제한 사용·특정 비용을 보장하지 않는다. 실제 호출은 계정의 사용량 및 모델별 제한을 따른다.

## 적용

프런트 변경이므로 production build가 필요하다. 실행 중인 job은 자동 중단/재개하지 않는다.
사용자가 작업 종료 후 데몬과 웹 서버를 재시작하고 화면을 새로고침하면 적용된다.
Cloudflare에 따로 배포한 화면은 별도 재배포가 필요하다.

## 검증 경계

오프라인 테스트는 선택 검증·웹 인증·wire 전송·Brief 저장/재개·역할별 런타임 요청 구성·기본값 호환을 검사한다.
로컬 CLI `model/list`에서 실제 모델/강도 메타데이터도 확인했다. 실제 모델 턴이나 보드 측정 작업을 시작한 검증은 아니다.
