# 네이티브 실행 구조

플랫폼은 Windows에서 Python 데몬과 Codex App Server를 직접 실행합니다. Docker Desktop,
WSL, Linux 컨테이너 이미지는 설치하거나 시작할 필요가 없습니다.

각 시나리오는 별도의 Git 작업공간을 사용합니다. Lead와 Verifier는 읽기 전용으로 작업하고,
Builder만 그 작업공간 안에서 파일을 수정하고 명령을 실행합니다. Builder 명령은 Codex의
`workspaceWrite` 샌드박스를 사용하며 네트워크 접근과 작업공간 밖 쓰기를 허용하지 않습니다.
외부 데이터시트 조사는 셸 네트워크 대신 Codex의 웹 검색으로 수행합니다.

작업에서 선택한 보드 구성은 job에 저장하며 데몬 전체의 지식 검색 옵션으로 정하지 않습니다.
새 USB/시리얼 보드의 연결 정보와 소스·문서도 같은 구조로 전달합니다.
Hardware 모드에서도 모델 셸에 장비 연결을 직접 제공하지 않습니다. 각 역할은 필요한
장비만 `check_connections`로 확인할 수 있고, 업로드·측정은 Builder가 요청합니다.
새 시리얼 장비는 Builder의 `serial_exchange` 도구로 통신합니다. 이는 프로그래머가
아니며 새 보드의 Flash 업로드에는 해당 실행기 구현이 필요합니다.
작업 시작 시 자동 연결 검사는 없으며 확인 결과는 원장에서 재사용합니다.
최종 응답으로 구조화된 장비 호출을 요청하면 호스트 어댑터가 설치된 하드웨어 프로필, 장비 identity,
전기적 한계와 작업공간 경계를 확인하고 실행합니다. 실행 파일 해시와 결과는 `runs/`와
job 원장에 기록합니다.

따라서 실행 경로는 다음 세 부분입니다.

1. Lead가 시나리오와 자료를 바탕으로 구현 방향을 정합니다.
2. Builder가 격리 작업공간에서 구현·빌드·테스트하고, 필요하면 장비 호출을 요청합니다.
3. 호스트가 장비 호출을 실행한 뒤 Verifier가 원래 시나리오와 산출물·실행 근거를 확인합니다.

기본 모드는 Hardware입니다. 장비 접근을 끄려는 경우에만 데몬에 `--profile offline`을
지정합니다. 실제 실행 명령은 [webui/RUNNING.md](../webui/RUNNING.md)에 있습니다.
