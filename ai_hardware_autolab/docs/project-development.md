# 내 프로젝트로 개발하기

플랫폼 설치 폴더와 개발 대상 소스 폴더는 서로 달라도 됩니다. 웹/데이터 분석/소프트웨어/연구 도구는 보드 등록 없이 같은 Lead → Builder → Verifier 흐름을 사용합니다.

## 최초 준비

- Windows, Python 3.11 이상, Git, Node.js 20 이상과 npm을 준비합니다.
- 데몬 PC에 Codex CLI를 설치하고 본인의 계정으로 로그인합니다. 현재 모델 선택은 이 CLI가 제공하는 모델 범위입니다. 모델 사용량은 해당 계정에 적용됩니다.
- 플랫폼 저장소에서 Python 의존성을 설치하고 프런트엔드를 빌드합니다.
- 개발 대상 폴더는 첫 커밋이 있는 Git 저장소여야 합니다. 아직 Git을 사용하지 않는 프로젝트는 그 폴더에서 git init, 파일 선별 추가, 첫 커밋을 진행하세요. 비밀번호·실험 원본·대용량 산출물은 대상 프로젝트의 .gitignore에 설정합니다.

## 실행

플랫폼 저장소 루트에서 별도 PowerShell 창 두 개로 실행합니다.

    .\scripts\run-platform.ps1 -Component daemon -ProjectRoot 'C:\Research\my-project'
    .\scripts\run-platform.ps1 -Component web

이 공유용 실행기의 기본값은 일반 개발(offline)입니다. Offline은 모델 호출을 끄는 옵션이 아니라 물리 장비 접근을 끄는 옵션입니다.

웹 서버가 출력한 전체 세션 URL을 엽니다. 실행기는 가상환경 .venv의 Python을 우선 사용합니다. 빌드는 README의 설치 단계에서 먼저 수행해야 합니다.

## 프로젝트 연결

Start → 내 프로젝트 연결에서 다음 정보를 저장합니다.

1. 이름과 소스 폴더의 절대 경로. 경로는 브라우저 PC가 아니라 데몬 PC 기준입니다.
2. 프로젝트 목적, 참고 자료 경로/URL과 개발 안내.
3. 빌드 방법과 검증 방법(선택). 이 문자열은 에이전트에게 전달되는 안내이며 플랫폼이 등록 즉시 실행하지 않습니다.

연결 후 이번 작업의 프로젝트에서 선택하고 시나리오를 입력합니다. 새 프로젝트 선택은 일반 개발 모드로 시작합니다.

예: CSV 로그의 결측치를 검사하고 그래프를 그리는 기능을 구현해줘. src/loader.py를 재사용하고, tests/의 회귀 테스트로 확인해줘.

## 소스와 결과

연결은 원본 폴더를 이동하거나 GitHub로 업로드하지 않습니다. 작업 시작 시 커밋된 소스와 무시되지 않은 변경/신규 소스를 별도 Git 작업공간으로 복사합니다. 일반 프로젝트의 src/, tests/, README 등 임의 소스 구조를 지원합니다. 원본 브랜치와 파일은 자동으로 변경하지 않습니다.

작업에 선택한 프로젝트 ID/소스 위치/개발 안내와 모델 설정을 고정합니다. 이후 다른 프로젝트를 선택하거나 안내를 바꿔도 진행 중인 작업은 기존 정보를 유지합니다. 연결 기록은 원장 옆 projects.json에 저장되어 재시작 후 재사용됩니다.

완료 결과의 파일과 작업공간 경로에서 변경을 검토하고 대상 저장소에 반영하세요. 플랫폼은 자동 merge/push를 수행하지 않습니다. 작업공간의 의존성은 대상 프로젝트 요구에 맞게 준비해야 하며, 일반 모델 명령의 네트워크 설치는 제한됩니다. 복잡한 의존성/외부 서비스가 필요한 경우 정확한 준비 방법을 시나리오와 README에 남기세요.

## 지식맵

- 프로젝트 필터와 프로젝트 가지에서 해당 프로젝트의 기록을 찾습니다.
- 기록을 선택하면 전체 본문, 코드 블록, 구현·검증 파일, 참고 문서와 조사 내용, 저장된 실행/측정 결과와 원본 기록을 볼 수 있습니다.
- 에이전트에게 재사용할 지식은 선택한 프로젝트 범위로 조회됩니다. 다른 프로젝트의 지식을 자동으로 가져오지 않습니다.
- 새 역할 결과의 상세 지식 메모와 참고 자료는 자동 적재됩니다. 에이전트 설명과 실제 호스트 반환 기록의 검증 상태는 구분합니다.
- 예전 기록에 상세 내용이 저장되지 않았다면 화면이 이를 새로 만들어내지 않습니다. 기존 원장/파일 근거가 필요한 기록은 별도로 확인해야 합니다.

## 하드웨어와 원격 화면

RTASE/BBB/PRU/CPLD/스코프는 포함된 하드웨어 활용 예제입니다. 일반 개발에는 해당 장비나 전용 툴체인이 필요 없습니다. 신규 보드의 자동 업로드는 해당 장비 어댑터가 있을 때만 가능합니다.

Cloudflare 원격 배포는 선택 사항입니다. 다른 연구원은 자신의 D1/토큰/릴레이 설정을 생성해야 하며 기존 연구실의 토큰·계정 설정을 복사하지 않습니다. 최초 프로젝트 연결은 로컬 웹에서 수행하세요. 원격 화면의 기능 범위와 설치는 webui/cloudflare/README.md를 참고하세요.
