# 신규 시나리오 단일 실행 흐름

신규 `mission` / `job.mission` 요청은 모두 Lead → Builder → Verifier 대화로 실행한다.
시나리오의 내용에 따라 다른 workflow로 전환하지 않는다. 코드 편집과 빌드는 job별
작업공간에서 수행하고, 장비 호출 결과는 `runs/`와 원장에 기록한 뒤 같은 대화로 돌려준다.

## 자료조사와 개발 반복

- Codex native web search를 `live`로 켜서 제조사 문서와 데이터시트를 검색하고 연다.
  셸 네트워크와 직접 장비 접근은 계속 분리하며 응답 형식 복구 턴은 검색도 끈다.
- 각 역할은 출처의 제목·URL·확인한 사실을 `sources`로 남긴다. 원장에 누적한 근거와
  실제 검색·페이지 열기 이벤트를 다음 역할에 전달한다. 출처 메모는 모델의 해석이며
  검색 이벤트 자체를 기술 사실이나 측정 증거로 간주하지 않는다.
- Lead는 원래 기능의 관측 가능한 완료 기준과 구현 방법을 정한다. Builder는 구현·빌드·
  프로그램·측정을 수행한다. Verifier가 미달을 발견하면 Lead 또는 Builder로 되돌아간다.
  동일 job에서 이 과정을 반복하며 기본 역할 턴 한도는 32회다.
- 장비 호출 전의 읽기 전용 입력 검사 실패는 `device_input_invalid`로 Builder에 반환한다.
  장비 핸들러 실행 중 예외는 결과 불명으로 남기므로 자동 재실행하지 않는다.
- 최종 결과에는 누적 조사 출처와 최종 Verifier가 인용한 해당 job의 run을 제공한다.

`search_policy=refresh`는 기존 근거가 충분하면 재사용하고 부족한 부분을 조사한다.
`always`는 핵심 자료를 다시 확인하도록 역할에 지시한다. 별도의 검색 완료 게이트는 없다.

## Hardware 모드

데몬은 `--knowledge-hardware`와 `--knowledge-revision`으로 현재 장비 연결 설정을
하나 선택한다. 이것은 시나리오별 실행 프로필이나 파일 허용 목록이 아니다.

- `ai_hardware_autolab/boards/rtase-v1/v1.0/hardware.yaml`: 장비 주소, identity, JTAG 연결,
  PRU 배포 위치, 스코프 채널과 전기적 한계
- `ai_hardware_autolab/boards/rtase-v1/v1.0/device-map.yaml`: SPI/JTAG/DAC/RF1 핀과 물리 연결

에이전트는 작업공간에서 코드를 만들고 도구와 일반 인자를 요청한다. `run_bbb`에는
작업공간 스크립트, `program_cpld_sram`에는 작업공간 XCF를 넘긴다. 호스트가 장비 주소와
실행 기록 이름을 정하고 실행 파일 해시를 기록한다. 요청마다 계약·프로필·허용 목록을
만들거나 선택하지 않는다.

## 자동 실행과 물리 경계

시나리오의 `CH3=RF1`, `RF1을 CH3로 측정해줘` 같은 명시적 채널 지정은 사용자 제공
배선 정보로 즉시 적용한다. 추가 연결 확인·승인을 요구하지 않고 에이전트가 capture
인자로 시간축·스케일·트리거를 설정한다. 지정은 원장 `conversation.scope.configured`에
기록하고 같은 설치 설정의 다음 job에서도 재사용한다. 후속 사용자 메시지로 바꿀 수 있다.

채널 지정이 없는 경우에는 기존 배선 정보를 사용한다. 필요한 신호의 연결 위치가
불명확할 때만 `needs_user`로 묻는다. 사용자에게 채널 정보를 받거나, 에이전트가 제안한
연결에 대해 `연결 완료`를 받으면 원장에 반영하고 같은 job을 계속한다. 모델의 제안만으로
배선 기록을 바꾸지는 않는다. 입력 전압·종단·감쇠 한계는 설치 설정에서 유지한다.
프로필 파일을 시나리오별로 편집하지 않으며 장비 run에 적용한 사용자 채널 지정을 남긴다.

- Hardware로 제출한 시나리오 안의 BBB 실행, scope 측정, JTAG scan, CPLD SRAM 프로그램,
  PRU 배포는 별도 Inbox 승인 없이 진행한다.
- 새 스크립트·설계·XCF·bitstream은 job 작업공간에 있으면 별도 등록하지 않는다.
- 호스트는 작업공간 밖 파일, 다른 endpoint/장비, 비휘발성 Flash 동작과 전기적 한계
  위반을 거부하고 실제 사용한 파일 해시와 결과를 run에 남긴다.
- 장비 접촉 뒤 결과가 불명확하면 자동 재실행하지 않는다.

Offline 모드는 장비 도구를 제공하지 않는다. Hardware 모드에서 짧은 시나리오를
제출해도 데몬에 선택된 기본 프로필을 사용하므로 보드 이름이나 과거 단계 번호를
매번 적을 필요가 없다.

## 적용과 검증

Python 변경 후 데몬을 재시작한다. 프론트엔드 변경 후 `npm.cmd run build`를 실행한다.
휴대폰 정적 화면에는 Cloudflare Pages 재배포가 추가로 필요하다. 실물 장비 검증은
새 job으로 수행하며, 플랫폼 회귀 테스트는 장비에 접촉하지 않는 모의 handler로 수행한다.
